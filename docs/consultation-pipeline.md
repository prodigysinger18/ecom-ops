# 咨询入口补全

`POST /api/v1/chat` 与 `POST /api/v1/agent/query` 共用入口检测和审计。

流程：用户与会话归属校验 → 敏感词检测 → 人工接管/灰度检查 → 通用问答或业务分流 → RAG/只读工具 → 失败兜底 → 保存回复和咨询追踪。

## 已实现的行为

- 敏感词命中：固定提示并建议人工处理，不调用 RAG、大模型和业务工具。用户消息只保存 `[敏感内容已拦截]`，短期上下文也不保存原文。
- 词表在 `data/safety/terms.json`，分类包含站外支付、索取凭证、辱骂、非法交易。支持 Unicode NFKC、大小写规范化、空格/标点/零宽字符移除。修改词表需要同步增加版本号；当前为保守词表匹配，不是完整语义安全审核，否定句和引用可能误报。
- 通用客服问题：使用已有知识库检索、证据生成和引用检查；知识不足转人工。
- 商品查询：查询实时本地商品服务；支持明确商品 ID、唯一完整名称或 SKU。含糊或同名商品要求补充信息，不猜测商品。数据库中的服务仍为模拟业务数据，未连接闲鱼。
- 订单、物流查询：使用已有只读工具，按订单号和用户 ID 联合查询，其他用户的订单不会返回。没有订单号先澄清。
- 修改/取消订单、改地址、改金额：明确转人工，既不直接修改订单，也不声称已修改。已有受控写接口用于工单、退货草稿和通知；订单修改执行接口尚未开放。
- 超出范围的问题：先说明支持的商品、订单、物流与售后范围，并提示可回复“转人工”；`handoff=false`，会话保持 `active`，不调用模型或工具。用户明确要求“帮我转人工”“找人工”等，才返回 `handoff=true` 并标记为待人工处理。不会自动创建工单或声称已有人工客服在线接入。其他原因的安全阻断、工具故障和受控写操作沿用既有兜底策略。
- 人工接管和灰度开关继续有效；敏感词检测在这两个判断之前执行。
- 未知会话 ID、其他用户的会话返回 404，不会悄悄创建新会话。
- 聊天服务异常返回固定兜底，并保存会话；Agent 工具失败使用既有异常处理和事件记录。

## 启动与试用

在项目文件夹打开终端，运行：

```powershell
python scripts/seed.py
python -m uvicorn app.main:app --reload
```

打开 `http://127.0.0.1:8000/docs`，点击 Authorize，输入开发客服令牌 `dev-agent-key`（若已自定义令牌，使用自己的值）。展开 `POST /api/v1/chat`，点击 Try it out，分别提交：

```json
{"user_external_id":"user-001","message":"退货条件"}
```

```json
{"user_external_id":"user-001","message":"商品库存","product_id":1001}
```

```json
{"user_external_id":"user-001","message":"查询订单","order_no":"ECO202610090001"}
```

```json
{"user_external_id":"user-001","message":"取消订单","order_no":"ECO202610090001"}
```

```json
{"user_external_id":"user-001","message":"私 下 转 账"}
```

FAQ 需要按 `docs/rag.md` 导入知识库，否则返回证据不足。百炼配置继续沿用 `.env`，本次无需重新填写密钥。

响应新增 `route`、`safety`、`consultation_trace_id`。路由为 `safety_block`、`faq_rag`、`business_tool`、`order_modify`、`clarification`、`fallback`、`human_request`、`human` 或 `service_failure`。

使用管理员令牌访问 `GET /api/v1/consultation-traces` 可查看请求 ID、会话、意图、词库版本、引用、工具/工作流事件、总耗时与入口检测耗时。详细检索排名、模型 Token 和各工具事件继续查看原有 RAG trace/ToolCall。聊天检索记录包含关联的 RAG trace ID。总耗时是服务执行时间，不包含网络往返和最后一次提交；不能直接等同用户体验延迟。

新增独立 `consultation_traces` 表；本地启动自动创建，不改动既有表列。生产部署应先创建对应迁移。停用可撤回两个入口的共用调用，保留追踪表用于复盘。

## 已测数据与面试表述

复跑：

```powershell
python -m pytest -q -p no:cacheprovider --junitxml=reports/consultation-tests.xml
python -m scripts.evaluate_consultation
```

最新完整回归 **157 passed**，包括入口拦截、规范化绕过、正常文本、两个入口的订单修改阻断、商品/订单分流、订单归属校验、缺参数澄清、FAQ 引用、异常落库、管理员审计权限、无效会话，以及超出范围提示后由用户明确申请转人工和否定表达不误转。

`reports/consultation-evaluation.json` 为独立可复跑的合成冒烟样本结果：

| 指标 | 样本结果 |
| --- | --- |
| 敏感内容召回 | 15/15（100%） |
| 正常样本误拦截 | 0/10（0%） |
| 静态路由正确 | 20/20（100%） |

这些小样本只验证规则与分支是否工作，不能证明真实用户准确率、零绕过或线上解决率。没有新增百炼调用，因此未产生本次真实模型延迟与成本评测。

面试可以说：“在既有 RAG 和 LangGraph 工具链前增加统一安全入口，阻断敏感内容和订单直接修改；实现业务分流、澄清、异常兜底及可追踪会话审计，完整自动化回归通过 149 项测试。合成冒烟集包含 15 个风险样本、10 个正常样本、20 个路由样本；生产效果仍需真实咨询集验证。”

后续应冻结人工标注的真实测试集，记录风险漏检率/误报率、通用与业务路由混淆矩阵、FAQ Recall@5/答案正确率/证据支持率、工具成功率、订单越权泄露数、端到端 P95 和实际 Token 成本。不要把上表填成线上数据。

身份边界：当前 Bearer 是内部客服/管理员令牌，`user_external_id` 由受信任客服端传入，并不等于生产用户认证。公开给终端用户前必须将用户身份绑定到认证凭证，不能信任客户端自行填写的用户 ID。
