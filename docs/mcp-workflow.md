# LangGraph通过MCP执行工具

`POST /api/v1/agent/query` 已默认采用 `AGENT_TOOL_TRANSPORT=mcp`。服务器选定能力集合后，由MCP客户端初始化标准stdio会话、发现只读工具，再调用订单/物流/库存/售后工具。知识检索仍在本地运行，模型不能任意选择协议工具。每次工具调用启动一个隔离子进程，调用完成自动关闭。

`AGENT_TOOL_TRANSPORT=local` 可回滚至直接业务函数调用。MCP故障不会自动绕过协议调用本地工具，而是转人工。单工具默认15秒超时，包括初始化与调用；工作流原有45秒预算仍有效。逐次启动子进程增加开销，后续应基于并发测试决定是否改为长生命周期连接池。

API在MCP模式下先提交校验后的会话和用户消息，再执行工具，以避免SQLite父事务持有写锁而阻塞独立MCP审计连接。工具成功/失败与remote_request_id保存至tool_calls；子进程按实际客服/管理员角色认证，独立审计与工作流事件可关联。

MCP子进程接收服务器当前DATABASE_URL，角色令牌通过进程环境传递，不放入工具参数。读取权限仍沿用可信客服身份及客户订单关联；共享客服令牌不等同于面向客户的个人身份认证。所有工具保持只读，无退款/补发/修改订单。

测试：`python -m pytest -q --junitxml=reports/mcp-workflow-tests.xml`。
真实协议验收：在已有演示账号/订单的开发数据库中运行 `python -m scripts.check_mcp_workflow`。该脚本保存一条测试会话及工具审计，不调用付费模型。

增量数据迁移：本阶段无新表或字段。配置默认由local改为mcp；已有.env可以显式设local回滚。回滚代码/配置时保留会话及审计记录，不删除数据。
