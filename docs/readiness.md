## 商品与订单预览

咨询成功返回 `previews` 卡片，包含服务端生成的本地详情链接及可核验字段。商品显示名称、SKU、库存、描述；订单显示订单号、状态、金额，不包含手机号和地址。普通咨询、用户咨询与 Agent 查询共用预览规则；失败、越权、范围提示及人工审核路径不展示卡片。

演示页点击“查看最新详情与链接”会在当前页面打开详情，使用请求头认证，不把令牌加入URL。详情接口为 `/api/v1/previews/products/{id}` 与 `/api/v1/previews/orders/{order_no}`，支持内部客服身份及用户JWT；用户订单必须归属当前身份，详情响应禁止缓存。单独复制接口链接访问需要认证，不是免登录分享链接。卡片取自本地业务数据库，MCP模式也会再次核验本地归属；尚不支持仅存在于远端的商品预览。

这里的链接是本项目业务详情接口，不是闲鱼链接。目前无真实平台商品URL和图片数据，不生成虚假的平台链接、价格或商品图。未来接入真实商品服务后，才可增加经过验证的外部商品链接与图片。

访问令牌是本系统身份凭证：内部客服开发默认 `dev-agent-key`，管理员开发默认 `dev-admin-key`；配置过自定义值时使用自定义值。已认证用户使用管理员签发的短期JWT，只能访问自己的数据。百炼API Key用于后端模型调用，不应填入页面“访问令牌”。正式用户登录后应自动取得用户令牌，目前演示采用人工签发。

## 1. 自然表达路由

通过共用的业务意图规则区分实时事实与通用资料，避免入口和执行器使用不同逻辑。

- “耳机还有现货吗”：实时商品工具；缺少唯一商品编号先澄清。
- “我买的东西怎么还没到”：物流工具；没有订单号先澄清。
- “把收货地点换成公司”：订单修改人工审核，禁止直接写订单。
- “库存管理规则是什么意思”：知识资料，不查询实时库存。
- “不要取消订单，我问退货规则”：不执行取消路径。
- 同时询问不同业务查询：先选择一项，不只回答其中一项却声称已全部完成。
- 商品服务没有价格字段时明确说明无法核验价格，不能用库存作为价格答案。

原120题是现在的开发回归集，107/120→120/120，是对已分析样本的修复结果，不是独立泛化准确率。

新60题单独冻结，文件与manifest见 `data/evaluation/routing-validation*`，测得58/60（96.67%）。来源是另行编写的合成问题，标签未人工审核；没有完全重复的问题，但不声称没有语义主题重合。保留的失败为“售价多少”表达漏判和“理财产品”被产品关键词误命中，没有为了满分改题或标签。

复跑：`python -m scripts.evaluate_routing_upgrade`。新验证集哈希不符时拒绝运行。不要重新执行build脚本覆盖已冻结文件；若用这批题继续调优，应另外采集最终盲测数据。

## 2. 身份与权限

内部客服/管理员继续使用现有staff令牌。面向用户的接口使用单独JWT，服务端从JWT的sub取得用户身份，不接受请求体指定user_external_id。

新增接口：

| 接口 | 权限与行为 |
| --- | --- |
| POST /api/v1/auth/customer-tokens | 仅管理员为已存在的用户签发短期JWT，并保存签发审计 |
| POST /api/v1/customer/chat | JWT绑定用户；只接受问题、会话、商品与订单参数 |
| GET /api/v1/customer/orders/{order_no} | 查询令牌身份所属订单，其他用户订单返回404 |
| GET /api/v1/customer/orders/{order_no}/logistics | 先校验订单归属再查物流 |
| GET /api/v1/customer/conversations/{id} | 仅返回自己的会话消息 |
| POST /api/v1/customer/logout | 数据库撤销当前JWT，立即停止该令牌后续访问 |

校验固定HS256算法、签名、签发方、受众、角色、时间、subject和token ID。客户JWT不能调用内部staff或管理员接口，staff令牌也不能冒充客户JWT。

本地`.env`已配置独立随机 `CUSTOMER_JWT_SECRET`，没有输出其值，至少32字节，不复用百炼密钥。生产部署必须另行管理独立签名密钥。默认有效期1800秒，上限3600秒。生产启动拒绝默认开发staff令牌和缺失的用户签名密钥。

管理员签发是可信发行入口，不是已实现平台用户登录。公开上线前仍需接入真实登录/平台身份验证、HTTPS、密钥管理、限流与目标数据库迁移。staff接口本来就是受信任客服入口，可选择用户，不应把staff密钥交给买家。

新增revoked_customer_tokens表。本地启动自动创建；生产使用正式迁移。过期撤销记录需定期清理，当前没有自动清理任务。

## 3. 人工审核工作台

- `/review`：审核120条候选问题的预期路由、参考答案和必要证据。
- `/answer-review`：审核真实模型报告中的240条回答、引用、是否正确、是否有幻觉，以及支持事实数。

两者需要管理员令牌，必须填写实际审核人并确认已核对。数据保留原始synthetic来源；不会因为审核通过就变成真实客户数据。使用etag/run_id/答案哈希拒绝过期审核和误绑定。

问题标签写入 `data/evaluation/holdout.json`。回答人审写入 `reports/expanded-live.reviews.json`。提交后根据实际审核量计算指标；没有标签时仍为null。

这两个文件工作台仅用于本地单进程审核，生产环境自动禁用。更新通过文件原子替换及进程内锁保护，不能用于多worker分布式标注平台。重跑真实评测会生成新run_id并覆盖同名审核模板，因此人审前应归档对应报告/模板，或用新的输出文件名保存下一轮。

## 4. 扩展知识库和真实对照

`data/rag/corpus-expanded.json`共24份合成演示文档，包括发票、保修、兼容、充电、续航、优惠券、错发、缺件、破损、定制、预售、地址和取消等。它们用于增加相近条款干扰，不能导入为正式商家政策。

本次使用同一60条FAQ候选问题、24篇资料、4个并发API客户端，完成每组60题共240次真实管线执行。各组均使用百炼Embedding、通义千问生成和独立生成审核；额外证据组只增加检索证据评估，不等于完整Self-RAG补检索对照。

| 方案 | 文档Recall@5 | 文档MRR@5 | 管线P95 | 模型支持状态数/60 | 已报告聊天Token总量 |
| --- | --- | --- | --- | --- | --- |
| 向量 | 1.0000 | 0.8167 | 6103.657ms | 43 | 33452 |
| 混合 | 1.0000 | 0.8861 | 5621.291ms | 42 | 33157 |
| 混合+重排序 | 1.0000 | 0.8944 | 10019.194ms | 42 | 71262 |
| 混合+重排序+证据评估 | 1.0000 | 0.8861 | 10977.054ms | 39 | 77955 |

“模型支持状态数”是生成与自动审核返回supported的数量，不是人工答案准确率。证据组15题被评估拒绝、6题生成证据不足；前三组各有1题独立生成审核失败并拒绝回答。人工Accuracy/Faithfulness/幻觉率仍为null。

MRR衡量正确文档的首个名次，不证明回答更准确。原标签只标注必要文档，扩展库存在等价替代证据，标签仍需人审；不要将此结果直接当成线上Recall或chunk级指标。Precision@5固定分母5，当前约0.2367，不与其他口径混用。

聊天Token包括返回usage中的生成、审核和增强；不包含Embedding、索引、未返回usage的失败调用。费用仍应核对实际价格及百炼账单。P95是实验管线耗时，有4客户端并发，不是用户请求的完整端到端生产延迟，也不能把不同方案顺序运行的耗时差全部归因于算法。

### 重排序的实际失败和修复

第一次完整实验中，重排序返回结果的候选编号校验导致大量整题失败，原报告保留于 `reports/expanded-live-before-fallback.json`。其调用事件此前只表示JSON成功解析，不能表示排列合法。

修复后，非法候选排列记录为invalid_ranking_ids，并回退原检索顺序，实验与正式服务的回退策略保持一致。复测两组分别触发32次回退，保留原证据，不再因为重排序格式问题丢弃整个请求。不能把回退后的结果说成“重排序全部成功”。

单次诊断可能返回合法排列，见rerank-contract-diagnostic.json；它不代表完整实验已经没有间歇性错误。规则和模拟响应测试证明回退路径，真实报告给出实际触发次数。

根据本次证据，重排序和Self-RAG默认关闭，并在本地`.env`关闭对应两项开关，能力保留，可在明确场景与独立评测证明收益后再开启。生成的引用校验和独立审核仍保留。

复跑命令（真实模型会产生API用量）：

```powershell
python -m scripts.benchmark_interview --live --corpus data/rag/corpus-expanded.json --workers 4 --output reports/expanded-live-next.json

python -m scripts.review_interview --report reports/expanded-live.json --reviews reports/expanded-live.reviews.json --output reports/expanded-live-reviewed.json
```

生产原知识库没有被扩展演示集替换，实验均在临时隔离库运行。并发实验每个工作线程有独立数据库会话，查询资料保持相同。

## 6. 演示启动

在项目文件夹终端执行：

```powershell
python -m scripts.run_demo
```

浏览器打开 `http://127.0.0.1:8001/demo`。默认使用离线证据回复，不额外调用百炼；原项目真实模型配置保持在`.env`中。

内部客服模式输入本地客服令牌；未自定义时为 `dev-agent-key`。点击售后政策、商品库存、订单查询、越权拦截、范围提示、主动转人工体验不同路径。越权示例使用已存在的订单和另一个已存在的用户，不用查无订单冒充越权验证。

用管理员令牌打开两个审核页面；未自定义时为 `dev-admin-key`。这些令牌是本地开发凭证，不能用于公网发布。

页面显示建议回复、引用、工具、路由、安全结果、请求关联和耗时，不保存令牌到浏览器存储，不自动向闲鱼发送消息。Ctrl+C结束演示。每次启动创建独立演示数据库，文件保存在reports/demo，便于复盘。

主服务继续用 `python -m uvicorn app.main:app --reload` 启动，新增功能无需更换百炼Key；本轮关闭的增强配置需要重启主服务生效。
