# 第四阶段：售后规则引擎

规则独立存放在数据库 `policy_versions.rules_json` 中，Agent 通过注册工具 `check_after_sale_policy` 调用。支持退货 `return`、换货 `exchange`、补发 `reship`、少件 `missing`、破损 `damage`、质量问题 `quality` 六类规则。

## 运行和演示

在项目根目录执行：

```powershell
python -m scripts.migrate_stage4
python -m scripts.seed_stage4
python -m uvicorn app.main:app --reload
```

种子脚本输出演示商品 ID。只在演示数据库运行种子脚本，其中 `demo-v1` 是虚构演示政策，不代表商家正式政策。不要在生产启动时自动导入它。

客服令牌调用 `POST /api/v1/after-sale/check`：

```json
{
  "user_external_id": "stage4-demo-user",
  "order_no": "STAGE4-DEMO-ORDER",
  "product_id": 1,
  "action": "return"
}
```

将 `product_id` 替换为脚本实际输出。聊天接口额外传 `product_id` 和 `after_sale_action`，例如消息“订单申请退货”。响应 `sources` 和工具记录保留政策版本，拒绝或未知结果提供对应会话的人工入口。

## 数据与判断语义

- `order_items`：用于核实商品属于订单。
- `order_after_sale_snapshots`：地区、签收时间和同步时间，须由受信业务平台同步。本阶段只提供数据模型，不伪造平台集成；聊天参数无法覆盖这些字段。
- `policy_versions`：版本、生效/失效时间、发布身份、完整规则、创建时间。
- 可配置商品白名单/黑名单、地区白名单/黑名单、状态白名单、签收后天数和凭证要求；空白名单表示所有商品或地区，黑名单优先。
- 生效时间包含端点、失效时间不包含端点。选取当前有效版本中生效时间最新者；生效时间相同时 ID 较大者优先。发布时间必须带时区，数据库统一存储 UTC。
- 期限为签收时间加 `window_days × 24` 小时，精确截止时刻仍符合资格，超过一微秒即超时。
- `eligible=true` 仅表示初步符合规则；实际商品状况、凭证和高风险动作仍需人工确认。`eligible=false` 表示已知不符合；`eligible=null` 表示数据、规则或关联信息不足。
- 三种结果都不会改变订单、退款或物流状态。不满足条件或无法判断时 `handoff=true`。

## 规则发布

管理员调用 `POST /api/v1/policies`，客服可调用 `GET /api/v1/policies`。同版本同内容重复提交返回已发布版本；同版本内容变化返回 409，必须发布新版本。版本发布与审计在同一事务中提交。

```json
{
  "version": "merchant-v1",
  "effective_at": "2026-10-10T00:00:00+08:00",
  "rules": [{
    "action": "return",
    "basis": "请填写商家核准的正式政策条款及来源",
    "allowed_statuses": ["delivered"],
    "window_days": 7,
    "excluded_product_ids": [],
    "excluded_regions": [],
    "requires_evidence": true
  }]
}
```

数字和内容是示例，发布前由商家核准。本阶段不对正式政策做默认推断。规则变化只需发布数据库版本，不修改 Agent 核心代码。

目前 `modified_by=staff:admin` 来自已有管理员认证身份，不接受请求正文伪造修改人；共享令牌无法区分具体员工。正式上线前应接入个人账户认证，将实际员工 ID 写入该字段。新接口面向已认证客服，不是供客户传入任意客户 ID 的公共接口。

## 迁移与回滚

迁移脚本仅创建三个新表，使用 `checkfirst` 可重复执行，不改动已有表或历史订单。已有 `startup/create_all` 同样能创建新表，但推荐部署前显式运行迁移。未完成数据同步的旧订单返回无法判定并提供人工入口。

回滚应用代码到第三阶段即可停用规则接口；保留新增表及审计数据，不进行自动删表。政策内容有误时发布一个新的修正版；需要恢复旧逻辑时将经核准的旧规则复制到新版本并立即生效，保留原始历史。备份数据库后再进行生产迁移；目前脚本已在 SQLite 验证，尚未在真实 SQL Server 环境验证。
